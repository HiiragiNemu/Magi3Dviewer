# Performance workspace UI baseline v2

## 目标
表演工作区必须像 3D 演出编排器，而不是把所有控件堆进一个可滚动对话框。一次屏幕内完成取景、选角、动作、骨骼、音频和时间线的常用操作；只允许内容区在需要时局部滚动。

## 固定布局（1440×900 基准，响应式缩放）
- **顶部 Transport（56 px）**：播放/暂停、停止、当前时间码、总时长、帧率、撤销/重做、保存。始终可见。
- **左侧 Outliner（260 px，最小 220）**：场景/角色/灯光/相机树；搜索和过滤固定在顶部；每个角色一行，显示可见、锁定、动画/物理状态。禁止把完整资源树塞进下拉框。
- **中央 Viewport（占剩余宽度，最小 640）**：唯一主画布；W/E/R 三色 gizmo、网格/地面、相机框、选中轮廓。拖拽只改变当前选择，不阻塞渲染线程。
- **右侧 Inspector（340 px，最小 300）**：仅显示当前选择的属性，分为 Transform、Skeleton/IK、Material、Physics、Visibility 五个可折叠区；未选择时显示提示，不展示巨型原始路径文本。
- **底部 Timeline（240 px，可折叠至 40）**：轨道列表、关键帧、音频波形、口型标记、吸附/循环/帧率。只有时间线横向滚动，页面和其它区域不滚动。

## 交互规则
1. 角色级操作优先：移动/旋转/缩放通过根骨骼或 IK 目标；衣服、头发、裙摆默认由统一物理组驱动，不为每个网格生成拖拽点。
2. gizmo 轴固定颜色：X=红、Y=绿、Z=蓝；平移与旋转模式明确分离；拖拽结束立即停止惯性，Esc 取消，Ctrl/Cmd+Z 可撤销。
3. 选中反馈持续可见（轮廓+轴+名称），不以一闪即逝的坐标提示代替状态。
4. 角色有独立暂停/继续；全局暂停不丢失物理和音频时间。
5. 动作采用 Clip 列表：默认待机、跑步、跳跃、攻击、受击；播放/停止/循环/速度在 Transport 或 Clip 行完成。
6. 音频轨道必须显示文件名、时长、波形和 actorKey 绑定；口型轨道显示时间标记并与音频同一时钟驱动。
7. 所有资源/场景/模型下载使用统一进度条：百分比、当前文件名、已载入/总量；失败显示可重试原因，不伪装成成功。

## 性能和可视化门槛
- 空闲工作区额外开销 ≤2 ms/frame；交互期间目标 60 FPS，最低 30 FPS。
- 单角色最多 24 个可见操纵手柄；默认只显示根、IK 目标和当前选中关节。
- pointerdown 到首帧反馈 ≤50 ms；禁止同步遍历全部网格或在拖拽事件中重建场景。
- 面板文字最小 14 px，主要按钮点击区域 ≥40×40 px；颜色对比 ≥4.5:1。
- 1440×900、1280×720、窄屏三档均无 body/document 滚动条；仅 Outliner、Inspector、Timeline 内部滚动。
