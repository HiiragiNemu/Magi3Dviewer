## 全库检查中新修复的真实代码问题

### 1. 敌方模型加载的异步失败与资源回收

`src/viewer/enemies/loader.ts` 原先先启动材质请求，再等待模型；模型先失败时，稍后材质拒绝可能变成未处理 Promise。现在立即观察两个请求，并保留原有结构化资源错误。纹理／绑定失败或加载中取消时，已解析但未投入使用的候选模型会被释放，临时纹理回收路径仍保留。

新增 `enemyLoadFailureLifecycle.test.mjs`，覆盖模型先失败、材质先失败、成功、纹理失败、绑定失败、取消与不具备可加载资源的情况；不是只覆盖成功路径。

### 2. 防穿地缓存没有响应移动／同 ID 替换场景

`src/viewer/editorGround.ts` 新增场景表面修订号及世界变换检查。即使角色或相机静止，只要地面移动或者同 ID 场景被替换，也会重新计算接触；原先只看角色／相机自身变换会漏过这类情况。

新增两条反例在修复前实测失败，修复后通过。保留静止、未变场景下的缓存，不通过每帧无条件全量碰撞换取正确性。

### 3. 单独打包入口误用 GitHub Pages 限制

`copy-deployment-public.mjs` 现在默认目标为 Cloudflare，显式区分 GitHub Pages，并拒绝拼错或无效目标。独立调用打包脚本不会因为默认落到错误平台而拒绝合法 Cloudflare 资源包。新增 9 条目标选择测试。

### 4. Windows 换行转换造成资源元数据校验失败

对 JSON 保留提交的原始字节，避免 autocrlf 把固定长度／摘要资源变成另一份字节流。恢复前检查没有用户未提交 JSON 数据修改，未把旧研究数据覆盖正式源码。测试里需要解析 TypeScript 文本的情况只规范化换行，不改变字段或数值。
